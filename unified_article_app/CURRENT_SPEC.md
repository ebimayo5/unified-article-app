# 統合版記事作成アプリ 現在仕様メモ

更新日: 2026-05-28

このメモは、今後の修正で古い仕様と混ざらないようにするための基準です。
迷ったら、このファイルを先に確認します。

## 目的

DRIVE BASE、たくみパパ、汎用記事の3つの記事生成システムを、1つのApps Scriptと1つの操作パネルに統合する。

基本方針:

- スプレッドシートは保存場所と候補確認の場所にする
- 実際の入力、生成、コピー、WP下書き作成はパネル中心にする
- DRIVE BASEとたくみパパはSEO記事 + WordPress下書き作成まで行う
- 汎用記事は納品用記事生成のみで、WordPress下書き作成は行わない

## キーワード候補シート

対象:

- DRIVE BASE_キーワード候補
- たくみパパ_キーワード候補

基本列:

| 列 | 内容 |
| --- | --- |
| A | 状態 |
| B | キーワード |
| C | 検索ボリューム |
| D以降 | 元データ貼り付け用 |

候補シートは、キーワードを広く貼って、次に書く候補を選ぶための場所。

運用:

- 候補シート全体を見ながら書くキーワードを選ぶ
- 状態を `書く` にする
- パネルまたはメニューから記事シートへ送る
- 送信後は候補側を `記事化済み` にする
- 記事化済み行はグレー表示にする

汎用記事には候補シートは不要。

## パネル

ファイル:

- `app_panel.html`
- `ua_web_app.html`
- `web_app.gs`

画面方針:

- 通常は大きいWebアプリ風画面で操作する
- 候補シートを開いて選ぶときは、スプレッドシートを見ながら操作する
- 候補から反映すると、記事編集画面に戻して生成を続ける

パネルでできること:

- 選択行の読み込み
- 行番号指定で読み込み
- 候補シートを開く
- 候補行を記事シートへ送る
- 読者心理メモ取得
- 本文生成
- WP下書き作成
- 投稿済みにする
- 本文、タイトル案、メタディスクリプション、パーマリンク、タグなどのコピー
- 記事生成モデルと読者心理モデルの表示、選択

## 読者心理メモ

読者心理メモは、本文にそのまま貼る素材ではなく、記事構成へ渡す設計メモとして扱う。

必須の整理:

- 顕在ニーズ
- 潜在ニーズ
- 読者の葛藤
- 導入文で拾う本音
- 見出し順のヒント
- FAQ候補
- 記事で深掘りすると刺さる判断軸
- 主役にしない補足テーマ
- 本文で事実として使わない方がよいもの
- 安全・法規・保証まわりの書き方ガード
- 本文で優先して扱う材料
- FAQに回す材料
- 今回は主役にしない材料

本文生成では、本文で優先して扱う材料を前半H2・比較表・判断軸へ優先反映し、FAQに回す材料はFAQや補足へ回す。今回は主役にしない材料は主軸にせず、必要に応じて内部リンク、関連補足、要確認ポイントへ回す。

## WordPress

対象:

- DRIVE BASE: 使用する
- たくみパパ: 使用する
- 汎用記事: 使用しない

現在は公開投稿ではなく、下書き作成まで。

WordPress接続情報はスクリプトプロパティで管理する。

DRIVE BASE:

- `UA_WP_DRIVE_SITE_URL`
- `UA_WP_DRIVE_USERNAME`
- `UA_WP_DRIVE_APP_PASSWORD`
- `UA_WP_DRIVE_CATEGORY_IDS`

たくみパパ:

- `UA_WP_HOME_SITE_URL`
- `UA_WP_HOME_USERNAME`
- `UA_WP_HOME_APP_PASSWORD`
- `UA_WP_HOME_CATEGORY_IDS`

共通設定:

- `UA_WP_DEFAULT_SITE_URL`
- `UA_WP_DEFAULT_USERNAME`
- `UA_WP_DEFAULT_APP_PASSWORD`
- `UA_WP_DEFAULT_CATEGORY_IDS`

注意:

- 通常ログインパスワードではなく、WordPressのアプリケーションパスワードを使う
- REST API制限があると403になる
- Cocoonのメタディスクリプション直接入力は現時点では見送り
- タイトル案は複数出すが、WP下書き作成時は先頭候補をタイトルに使う

## 内部リンク

ファイル:

- `links.gs`

内部リンクシート:

| 列 | 内容 |
| --- | --- |
| A | サイト |
| B | URL |
| C | タイトル |
| D | メタディスクリプション |
| E | 本文冒頭 |
| F | 関連キーワード |
| G | 核記事 |
| H | 取得日時 |
| I | 手動保持 |
| J | 使う場面 |
| K | 優先度 |

対象:

- DRIVE BASE: 使用する
- たくみパパ: 使用する
- 汎用記事: 使用しない

サイトマップから自動取得する。

スクリプトプロパティ:

- `UA_INTERNAL_LINK_DRIVE_SITEMAP_URL`
- `UA_INTERNAL_LINK_HOME_SITEMAP_URL`
- 共通 fallback: `UA_INTERNAL_LINK_SITEMAP_URL`

現在の仕様:

- 最大取得URL数: 200
- 本文冒頭取得文字数: 260
- 本文生成に渡す候補数: 最大8件
- 同じサイトの記事だけを候補にする
- キーワード完全一致だけでなく、日本語の部分一致と関連語も使う
- `使う場面` と `優先度` はサイトマップ更新時に自動補完する
- 候補がある場合は、本文内に1個以上入れる前提でAIに検討させる
- ただし関連性が薄い候補は使わない

## プロンプト方針

ファイル:

- `prompt.gs`

共通:

- WordPressコードエディターに貼れるHTMLを出す
- H1は使わない
- 導入文のあとに「この記事のポイント」を入れる
- Q&Aのあとに必ずまとめを入れる
- タグは8〜10個を狙う
- 要確認ポイントは最大5個
- AI Overviewに拾われやすいように、H2直下に自己完結した答えを置く
- 表の前後に短い要約を入れる
- 体験談と事実確認が必要な説明は混ぜすぎない

DRIVE BASE:

- 車メディア
- 整備士専門学校、整備工場研修、大型トラック運転経験を自然に使う
- 商品提案は売り込みではなく、選ぶときのポイントとして入れる
- 洗車、車内清掃、コーティング、タイヤ、電装品、車中泊用品では、必要に応じて商品カテゴリを提案する
- 具体的な商品名、型番、価格ランキングは出典や案件指定がない限り断定しない

たくみパパ:

- まだ家を建てていない生活者目線
- 一人称は「僕」
- 古い実家暮らし、家族、長男の車いす視点をテーマに合う場合だけ自然に入れる
- 家を建てた経験者のようには書かない
- 設備、掃除、収納、家事、外構、防災、子育て、車いす動線では、暮らしの負担を減らす商品カテゴリや設備カテゴリを提案してよい
- 売り込みではなく、暮らしの選択肢として扱う

汎用記事:

- 案件指示書をA列に入れる
- キーワード候補シートは使わない
- WordPress下書き作成はしない
- 内部リンクは使わない
- 外部リンクは公式・公的・メーカー公式など、信頼性補強の目的で使う

## 今後の修正で注意すること

- 似た関数名が多いので、修正前に対象ファイルを確認する
- `config.gs` の列数と、シート側の列数をずらさない
- `汎用記事` にWordPress機能を混ぜない
- 内部リンクは候補を広げすぎるとAIが無視しやすい。関連性のある候補だけ出す
- 外部リンクは出典シート優先。ただし公式URLが確実なら補完してよい
- 商品提案は出してよいが、ランキングや価格の断定は避ける
- コピペ用にApps Scriptへ貼るファイル名とHTMLファイル名の重複に注意する
- コンテキストが長くなったら、この仕様メモを読み直してから作業する
